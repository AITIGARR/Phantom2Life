# Phantom2Life 1.4.0 — Fabric 1.21.11 + Polymer

**Настоящие серверные кастомные блоки** `naviyosha:invisible_sign` и `naviyosha:invisible_wall_sign`, в отличие от версии 1.3.0, где использовался ванильный pale-oak sign, и 1.2.3, где использовались text_display/interaction.

Требования на сервер: Java 21, Fabric 1.21.11, Fabric API, **Polymer Core 0.15.2+1.21.11** (проще установить Polymer bundled 0.15.2+1.21.11). Клиентский мод не нужен. Игроки должны принять ресурспак.

## Что происходит
- Мембрана фантома + любая обычная табличка (12 древесин) даёт отдельный серверный предмет `naviyosha:invisible_sign`.
- Предмет ванильным SignItem сразу ставит блок `naviyosha:invisible_sign` (на полу) или `naviyosha:invisible_wall_sign` (на стене).
- На сервере хранятся эти ID, а не `minecraft:pale_oak_sign`.
- Polymer отображает их ванильному клиенту как подходящие pale-oak sign blockstates со всеми направлениями; серверные блоки сохраняют SignBlockEntity и ванильные инструменты для редактирования текста.
- Для скрытия деревянной основы ресурспак делает текстуру pale_oak sign прозрачной. Текст рисует Minecraft, а не display entity.
- Уже установленные старые таблички из 1.3.0 автоматически **не** преобразуются; их нужно заменить новыми. Старые display-сущности версии 1.2.3 сохранены только для обратной совместимости.

## Ограничение рендера
Polymer добавляет **отдельные серверные ID блоков**, но ванильный клиент видит только подменяющие ванильные состояния. Поэтому **все** настоящие pale-oak таблички становятся прозрачными, пока активен данный ресурспак. Иначе сделать выборочно прозрачной лишь одну sign-модель без клиентского мода с обычным sign text renderer нельзя. Остальные 11 типов дерева остаются без изменений.

## Рамки
Существующие бесформенные рецепты мембрана + рамка / светящаяся рамка сохраняются без изменений.

## Установка
1. Поместите `Phantom2Life-1.4.0.jar` в `mods` на сервере, рядом с Polymer Core или Polymer bundled и Fabric API.
2. Подключите `Phantom2Life-resource-pack-1.4.0.zip` клиентам через `server.properties`, например:
   ```
   resource-pack=https://YOUR-HOST/Phantom2Life-resource-pack-1.4.0.zip
   resource-pack-sha1=SHA1_OF_THE_ZIP
   require-resource-pack=true
   ```
3. Перезапустите сервер. Для тестов используйте копию мира.

## Проверка
GitHub Actions компилирует и публикует JAR/ZIP; **успешная сборка не равна проверке поведения в запущенном Minecraft**. Проверьте в игре: крафт, установку на пол/стены, четыре строки с обеих сторон, обычное редактирование, красители, воск, разрушение, выпадение, повторную установку, перезагрузку сервера и подключение второго игрока. Флаги здесь пока не реализованы.

## Ресурспак: исправление чёрных табличек (Minecraft 1.21.11)

На некоторых клиентах полностью прозрачная RGBA(0,0,0,0) текстура обычного sign atlas отображается **чёрной прямоугольной табличкой**. В исправленном ресурспаке текстура `pale_oak.png` заменена единым маркером RGBA(17,29,41,15), а `assets/minecraft/shaders/core/entity.fsh` принудительно отбрасывает именно этот маркер. В стандартном рендере alpha-cutout также отбрасывает текстуру. Текст SignBlockEntity должен остаться ванильным.

**Важно:** это графический workaround, а не исправление Polymer API. Шейдеры и альтернативные рендереры на Android, Iris, Sodium или OptiFine могут игнорировать или переопределять core shaders. Не гарантируется, что фикс заработает на каждом клиенте — тестируйте сначала с выключенными внешними шейдерами и только с Phantom2Life ZIP. Сравните с объединённым JabaCraft-паком. **Все** бледно-дубовые таблички по-прежнему прозрачны. Другие ресурспаки, меняющие `entity.fsh`, могут конфликтовать.
